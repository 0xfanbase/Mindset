# v1.28 — duo audit (Opus 5 + Fable 5, blind) → synthesis → Fable director fix round

A different review shape than v1.20/v1.27's single-reviewer passes: two full code-quality +
UI/UX audits ran against this repo **independently and blind to each other** — one on Opus 5,
one on Fable 5 — followed by a synthesis pass that compared the two reports against each other
AND against the real project history (git log, `audits/decisions.md`, the BUILD-PLAN changelog)
to adjudicate the places they disagreed. A Fable project-director fix round (this one, with
full write access) then decided what actually ships, implemented it, and verified it live.
Findings both models caught independently with matching verification were treated as
highest-confidence; everything was still re-confirmed against the current tree before any edit.

## Method (director round)

- Re-verified every finding against the actual code before changing it — greps and reads first,
  never trusting the synthesis's line numbers (they had drifted in places; one claimed
  email/phone sweep in verify.mjs turned out not to exist at all, which only strengthened the
  finding it supported).
- Playwright + the pre-installed Chromium, serving the repo from disk via request interception
  (no dev server, per house convention), `page.clock` for frozen/advanced time, forced-failure
  fetch routes for error paths. The one finding whose brief demanded it (the resume-date
  freeze) was reproduced on the **unpatched** code first, then re-run post-fix with the same
  script, including a regression assertion for the pre-existing v1.16 behavior.
- `node scripts/verify.mjs all` plus `--input-type=module --check` on touched JS after every
  change; the one new verify.mjs check was mutation-tested (inject → exactly that check fails →
  revert → clean) per the discipline this repo has held since v1.23.
- Everything logged in `audits/decisions.md` (entries dated 2026-07-24), including what was
  deliberately not fixed.

## What shipped (by the adjudicated finding list)

**Tier 1 — both fixed.**
1. **PII (invariant 1):** the owner's wife's first name appeared three times in v1.24 prose
   (BUILD-PLAN.md twice, decisions.md once) — live on Pages, since the deploy uploads the whole
   repo. All three scrubbed; a base64-encoded name-denylist check added to verify.mjs
   (74 → 75, mutation-tested); `robots.txt` `Disallow: /` added as cheap defense-in-depth.
   The name remains in two already-pushed commits (`1c2d2b8`, `a6b5c79`, re-confirmed as
   `origin/main` ancestors); purging those needs the history rewrite invariant 10 prohibits —
   **flagged for the owner's explicit decision, not acted on.**

   resuming a backgrounded PWA a day later in the same mode kept date line, cards, and chip
   frozen indefinitely. Reproduced unpatched, fixed by memoizing the painted HKT date alongside
   the mode (weeks.js's own `refreshIfStale` pattern), re-verified with the mode-flip
   regression intact.
